# 设计项目启动包

这是把“审美积累”转成“可执行项目”的入口。它适用于新的 App、响应式网页、后台工具、营销站、服务体验和其他数字界面项目；不是所有项目都要填写全部文件。

开始项目前，先从本库选择与任务有关的**参考、拆解或机会假设**；它们只能提供问题、质量或试验线索，不能替代用户研究、业务事实、PRD 或平台规范。可复用本地资产还要另行核对来源、许可、完整性与项目适用性。

## 先选执行深度

| 深度 | 适用情形 | 最小交付物 | 审核要求 |
|---|---|---|---|
| 轻量 | 单页、概念验证、低风险内部方案 | 项目简报；关键流程与页面状态；创意方向与 Taste 基线；交付检查 | 至少一次自检；明确未验证项 |
| 标准 | 可用产品功能、完整专题站、中等协作成本 | 七类核心模板按适用性填写；必要的界面系统；可点击原型 | 过程与产出由不同任务独立审核 |
| 上线级 | 面向真实用户、品牌或业务结果、多人交付 | 全部核心模板、版本证据、全状态、可访问性和交付包 | 双独立审核；阻断项清零后才可声明可交付 |

以下情况至少使用“标准”：涉及多人协作、多个关键流程、跨端适配、长期迭代或品牌资产。涉及支付、隐私、健康、安全、无障碍承诺或正式上线时使用“上线级”。

## 六道门禁

| 门禁 | 必须回答的问题 | 通过证据 |
|---|---|---|
| D0 问题成立 | 为谁解决什么问题，成功如何判断？ | 已批准的项目简报与非目标 |
| D1 流程成立 | 用户能否完成关键任务，异常时怎么办？ | 信息架构、任务流、状态矩阵、原型验证 |
| D2 Taste 成立 | 设计表达是否有明确意图、判断标准和边界？ | Taste 基线、参考与反参考、方向审核 |
| D3 系统成立 | 页面、组件、状态和跨端规则是否一致？ | 变量/组件策略、响应式与平台规则 |
| D4 交付成立 | 实现者能否无猜测地还原？ | 标注、资产、文案、状态、验收清单和版本 |
| D5 学习闭环 | 哪些经验可复用，哪些只是本项目特例？ | 复盘；经验证的卡片/主题合集；EVO 候选 |

不得跳过 D0、D1、D2 直接把高保真视觉当作方案完成。门禁可以合并记录，但结论必须有证据。

不确定填写到什么程度时，先看 [`示例_任务管理应用启动摘要.md`](示例_任务管理应用启动摘要.md)。示例只展示判断深度，不提供可复制的视觉答案。

## 30 分钟启动法

1. 用 5 分钟写清任务来源、目标、受众、平台、约束与非目标。
2. 用 10 分钟盘点现有素材、竞品、平台规范和事实缺口；区分事实、假设和偏好。
3. 用 10 分钟画出一个最关键任务流，列出加载、空、错、权限不足和完成态。
4. 用 5 分钟写下 3～5 条可观察的 Taste 标准，以及至少一个反参考。
5. 冻结执行深度和下一门禁，不在范围未定时批量制作页面。

## 按项目类型适配

- **iOS / iPadOS**：以 Apple Human Interface Guidelines 和当前平台行为为准，检查动态字体、VoiceOver、减少动态效果、触控目标和多尺寸适配。
- **Android**：以当前 Material 指南和平台行为为准，检查系统返回、组件状态、动态配色和不同窗口尺寸。
- **响应式 Web**：默认以 WCAG 2.2 AA 为目标，覆盖键盘、焦点、缩放/重排、触控与鼠标、慢网和断网。
- **营销站 / 品牌站**：加强叙事、信息节奏、内容证据、转化路径、性能与素材版权；不因“视觉型项目”省略可访问性。
- **内部工具 / 后台**：优先任务效率、信息密度、可扫描性、批量操作、错误恢复与审计，不强加消费级视觉风格。

## 使用边界

- 设计系统不是必选答案。单页低复用项目可以只定义最小变量和局部规则；规模与复用成立后再扩展。
- 外部参考用于理解模式和质量，不用于复制他人的界面、品牌或资产。
- 市场、平台与工具事实会变化，需要使用当前官方资料重新核验。
- “已完成”“可开发”“可上线”必须绑定具体版本、审核结果和适用范围。
