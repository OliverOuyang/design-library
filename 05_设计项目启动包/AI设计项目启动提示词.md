# AI 设计项目启动提示词

复制下方 Prompt，在方括号处补充信息。除“项目绝对路径”外，其余未知项可以保留为空；AI 应先盘点再提出最少量的阻断问题。

```text
如果当前环境可用 $shape-project-with-taste，请使用它治理并启动这个设计项目；如果不可用，不要中断，直接按本提示词与「05_设计项目启动包/README.md」执行等价流程。

项目绝对路径：[必填]
项目目标：[可选]
项目类型或平台：[iOS / Android / 响应式 Web / 营销站 / 后台工具 / 未确定]
目标用户与关键场景：[可选]
当前阶段：[新项目 / 已有需求 / 已有线框 / 已有视觉 / 待交付]
希望执行深度：[轻量 / 标准 / 上线级 / 请诊断]
已有材料：[PRD、品牌规范、研究、设计稿、代码、数据等；可空]
硬约束：[时间、技术、品牌、合规、预算；可空]
喜欢的参考与原因：[可空]
不喜欢的反参考与原因：[可空]
本次希望优先完成：[可空]

请先读取项目内已有 README、需求、设计、代码、版本与治理文件，确认实际工作树和事实，不依据旧对话猜测。再读取本库的「05_设计项目启动包/README.md」，只选择与本项目类型、风险和阶段匹配的模板，不机械生成全部文档，也不要覆盖已有真源。

执行要求：
1. 先区分事实、假设、偏好、未知和阻断项，确定项目主类型、执行深度、基础工程与门禁。
2. 在实施前调研当前用户需求、同类产品、成熟模式、平台官方规范和可复用工具；形成 Build / Borrow / Adapt / Defer / Reject 决策，不为展示工作量重复造轮子。
3. 先完成问题定义、用户任务、信息架构、关键流程和完整状态，再进入高保真视觉。
4. Taste 是首要质量合同：明确设计意图、3～5 条可观察标准、参考与反参考、层级、密度、节奏、色彩、字体、动效和“会破坏可信度的细节”。不得用通用渐变、大卡片堆叠或无意义动效代替判断。
5. 按最终可上线标准设计路线，但按当前阶段渐进加深；轻量项目可合并记录，上线级项目必须保留版本化证据。
6. 覆盖与项目匹配的加载、空、错误、权限、离线、长内容、本地化、键盘/焦点、减少动态效果、响应式和破坏性操作等状态。
7. 核心文档使用清晰、规范的中文名；面向我检查的 Markdown 和核心代码应有易懂中文说明。不要为了中文化破坏生态约定、导入路径、公开 API 或工具识别。
8. 标准和上线级项目安排两个独立任务：过程审核检查范围、证据、版本与门禁；产出审核检查可用性、完整性、Taste 和交付质量。实施任务不得自签通过。
9. 每次结束前更新项目接续记录，写明已完成、证据、当前版本、未决项、风险和下一步。只有经项目验证的通用经验才可反向沉淀到本库，作为 EVO 候选，不能把项目特例直接升级成规范。

请先输出并执行：项目诊断、所选模板、保留/新增/不做清单、第一阶段门禁及验证方式。清晰且可逆的本地工作直接继续，不要停在“是否开始”的询问上。
```

同一项目新开 Session 时，把第一行改为：

```text
如果当前环境可用 $shape-project-with-taste，请以 RESUME_EXISTING_PROJECT 模式继续这个设计项目；如果不可用，先读取当前 Git、项目接续记录、已批准文档和审核证据，再按本提示词继续。
```

并至少提供项目绝对路径。旧聊天摘要只作为线索，不得覆盖当前项目证据。
