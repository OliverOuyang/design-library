> 用途：验证流程、理解和包容性，而不是证明设计者原本就对。标准/上线级项目必用；Web 上线级默认以当前 WCAG 2.2 AA 为目标。

## 可访问性检查

- [ ] 语义与名称：标题、区域、控件、状态变化可被辅助技术理解。
- [ ] 键盘与焦点：所有操作可完成；顺序合理；焦点可见；无陷阱。
- [ ] 对比与非颜色信息：文字、控件、焦点和状态不只依赖颜色。
- [ ] 缩放与重排：放大后无关键内容丢失或双向滚动障碍。
- [ ] 触控与手势：目标足够可操作；复杂手势有替代方式。
- [ ] 动效、闪烁和声音：支持减少动态效果；声音有视觉 / 触觉替代。
- [ ] 表单与错误：标签、说明、格式、错误位置和恢复动作明确。
- [ ] 图片、视频与音频：替代文本、字幕、文字稿按内容目的提供。
- [ ] 文案与认知负担：语言直接；步骤、时间限制和不可逆后果清晰。
- [ ] 真机与辅助技术：按平台至少完成代表性组合，不只依赖插件评分。

## 未验证边界

明确写出未测试的平台、用户、语言、内容和技术限制，以及由谁在何时补齐。未验证不能写成“默认通过”。
