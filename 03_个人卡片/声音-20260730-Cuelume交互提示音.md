# Cuelume：把交互音效做成声明式行为映射

## 观察

- 官方页面和上游仓库都把对象限定为“交互声音调色板”，不是通用音频引擎：14 个提示音在播放时由 Web Audio 合成，不下载或加载录音文件。
- `data-cuelume-press` 与 `data-cuelume-release` 把一次点击拆成按下和抬起两个时点；这迫使设计者先说清反馈发生在哪一刻，而不是为按钮泛加一声响。
- 默认行为具有节制边界：按 README／源码实现，hover 只面向精细指针，连续 hover 有 150ms 全局节流；toggle 遵循原生 click，因此包含键盘激活。库也提供全局音量与关闭开关；浏览器阻止 Web Audio 或名称无效时静默退化。官网 demo 同时写有“触摸时轻点也会触发”的说明；本轮未运行实时 demo，不据此断言实际触摸行为。

## 可迁移点

- 先按任务语义定义小词表：探索（hover）、承诺（press／release）、状态翻转（toggle）、完成（success）、可恢复错误（error）、等待开始（loading）和内容就绪（ready）。不要从“找一个好听的点击声”开始。
- 将声音偏好交给产品设置；视觉、文字或触觉仍须能独立解释结果。Cuelume 的 `setEnabled(false)` 提示了“关闭后不播放”的最低边界，但不等于某个产品已经完成无障碍验证。
- 对密集控件优先控制触发频率、响度和可重复性；先用低保真原型验证是否增加理解，再决定是否投入品牌声设计。

## 边界与避坑

- 这是对公开文档和源码说明的拆解，不是对某个真实产品成效的证明；没有用户研究、转化或可访问性结论。
- Cuelume 是 ESM-only，目标为支持 ES modules 与 Web Audio 的现代浏览器；服务端导入安全，但播放只在浏览器发生。技术采用时必须重新核验当前版本、许可证、浏览器支持与自身隐私／偏好设置方案。
- 本卡不下载、复制或再分发任何声音、代码或界面截图；MIT 许可证只说明上游代码许可，不自动构成本库或未来产品的采用决定。

## 任务与状态

- 用户要完成的任务：在保存、切换、启动等待或得到结果时，确认系统是否理解并响应了自己的操作。
- 触发与前置条件：由带 `data-cuelume-*` 属性的可交互元素触发；应用启动后调用一次 `bind()`。按 README／源码实现，hover 仅在精细指针下触发；官网 demo 对触摸轻点的说明与此不同，真实项目应在目标设备实测。
- 前后状态／反馈：按下／抬起形成两段反馈；toggle 对应状态翻转；success、error、loading、ready 供应用按自身状态调用。音量可在 0–1 范围内设置，也可以关闭后续播放。
- 加载、空、错、权限、离线或中断边界：`loading` 只表示用户发起工作，不表示加载完成；`error` 被建议用于可恢复错误。Web Audio 不可用或浏览器阻止播放时为静默 no-op，因此页面必须保留可见的状态与错误反馈。
- 键盘、读屏、减少动态或替代反馈：toggle 沿用原生 click，源码说明包含键盘激活；hover 的触摸行为在官网 demo 文案与 README／源码间不一致，不能将它用作触摸探索保证。上游未提供读屏、减少动态或触觉策略；真实项目应让声音成为可关闭的补充，不依赖声音传递唯一语义。
