# 执行与版本管理规范

> 文档职责：规定文件修改、版本锚点、命名、回滚、归档与发布声明边界。
> 当前状态：执行制度已批准；实际版本状态只见 07。
> 适用范围：全项目。
> 权威来源：实际工作树、01 版本路线、素材清单与 07 台账。
> 最后更新：2026-07-30。
> 更新触发：版本控制、文件命名、资产操作、归档或回滚方式改变。

## 修改纪律

- 修改前确认当前目录、适用指令、受影响真源和已有未提交内容；不以旧对话判断完成。
- 人工审阅文件使用清晰中文名；机器敏感的 JS、HTML、URL、资产 ID 与构建路径保留现有 ASCII／工具约定。不得以“中文化”破坏预览、哈希或链接。
- 一个事实只在其真源维护：运行时库存改 Manifest，版权／哈希改素材清单，动态项目状态改 07。
- 批量删除、覆盖、重命名或替换资产前，列出精确目标、依赖和回滚路径；未验证引用时先保留旧入口或建立迁移映射。

## 版本与回滚

| 场景 | 必需动作 | 回滚锚点 |
| --- | --- | --- |
| 文档／模板变更 | 复核链接、职责与 06 对应检查；记录 07 | Git commit；在 Git 建立前保存变更前哈希与文件清单 |
| 新增／替换本地素材 | 同步清单、Manifest、预览与哈希；独立审核 | 旧文件和旧哈希，或 Git commit |
| 外部资料采用 | 在 10 记录当前复核结果和不采用部分 | 删除项目特定采用记录，不改写历史决定 |
| 正式发布声明 | Git 或等价不可变快照、全部相关门禁和独立审核 | 已验证的上一稳定版本 |

若项目缺少 Git 不可变快照，首次初始化后应先提交完整基线并在 07 记录 SHA；随后采用单一意图提交及项目上级要求的 Lore 提交协议。初始化或提交前不得将本库称为已发布版本。是否存在该缺口只由 07 的当前卡声明。
