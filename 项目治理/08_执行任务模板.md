# 执行任务模板

> 文档职责：提供可复制的、边界明确的收录、素材、启动包、审核与修复任务合同。
> 当前状态：可用；不替代具体项目的 02／03 合同。
> 适用范围：本库维护和由本库启动的设计项目。
> 权威来源：00–07、09–10 与实际任务材料。
> 最后更新：2026-07-30。
> 更新触发：角色、门禁或交接流程改变。

> 路径约定：本文件中反引号文件路径均相对项目根目录。

## 任务合同

每个任务开头必须写清：目标、非目标、精确路径／资产 ID、当前版本锚点、事实来源、风险等级、完成证据、回滚锚点和唯一交接对象。未知事实可保留为假设，但不能被写成已验证结论。

| 任务类型 | 最小步骤 | 完成定义 |
| --- | --- | --- |
| 收录卡片／合集 | 识别来源 → 写观察／迁移／边界 → 按分类与标签检查 → 更新对应入口 | 可检索，字段完整，无重复或“其他”桶 |
| 新本地素材 | 确认权利 → 收集满 5 项最小类 → 写清单 → 更新 Manifest／预览 → 哈希与人工检查 | 02 与 06 完整，独立审核结论可追溯 |
| 新设计项目启动 | 选执行深度 → D0 问题、D1 流程、D2 Taste → 选择所需模板 → 冻结下一门禁 | 项目合同完整，未把参考或假设当事实 |
| 审核 | 固定输入 → 只读检查 → 给出 P0／P1／P2 与结论 → 写 09 | 与实施分离；不修改后自批 |
| 修复／迁移 | 记录发现 → 由实施者最小修改 → 复验 → 开新一轮审核 | 旧结论保留，回滚锚点仍可用 |

## 治理重整审核合同

当 07 的当前卡打开“治理重整审核”时，固定治理包为：`SESSION_CONTINUE_PROMPT.md`、`README.md`、`更新记录.md`、`项目治理/README.md`、`项目治理/00_总路线与决策记录.md`、`项目治理/01_版本路线图.md`、`项目治理/02_分类法来源与版权合同.md`、`项目治理/03_整理检索与使用方案.md`、`项目治理/04_执行与版本管理规范.md`、`项目治理/05_独立审核SOP.md`、`项目治理/06_验收门禁与验证矩阵.md`、`项目治理/07_变更日志与迭代台账.md`、`项目治理/08_执行任务模板.md`、`项目治理/09_共识交接与评审记录.md`、`项目治理/10_外部调研与引入门禁.md`。比对材料为 `素材资产/assets-manifest.js`、`素材资产/素材清单与许可.md`、`04_规则与模板/收录规范.md`、`05_设计项目启动包/README.md`。

审核人只读，固定输入为上述 15 个文件与 4 份比对材料的 SHA-256；结论写入 09。先后顺序由 05 与 06 规定：过程审核无阻断项后，另开任务对同一固定包做独立产出审核；两者不得由同一任务替代。当前处于哪一步、唯一下一步和已关闭门禁一律以 07 为准，本模板不保存动态任务状态。
