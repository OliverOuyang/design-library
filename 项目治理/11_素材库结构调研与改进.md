## 一、调研结论：一个好用的素材库要满足什么

| # | 结论 | 来源 |
|---|---|---|
| 1 | 文件夹层级要浅；一个素材只放在一个文件夹，其他维度靠元数据和标签找，不靠复制 | [Adobe：AEM Assets 文件夹结构最佳实践](https://experienceleague.adobe.com/en/perspectives/folder-structure-best-practices-for-aem-assets)、[ResourceSpace：元数据最佳实践](https://www.resourcespace.com/blog/4-metadata-best-practices-digital-assets) |
| 2 | 元数据至少要有：类型、作者、日期、使用权；命名统一、可读、唯一 | [Hyland：DAM 最佳实践](https://www.hyland.com/en/resources/articles/digital-asset-management-best-practices)、[Pics.io：文件命名](https://blog.pics.io/best-practices-for-digital-asset-management-file-naming-conventions) |
| 3 | 许可证用 SPDX 标识，全文放在根目录 `LICENSES/<SPDX>.txt`，每个文件都能查到版权和许可 | [REUSE 规范 3.3](https://reuse.software/spec-3.3)、[SPDX 许可证列表](https://spdx.org/licenses) |
| 4 | Git 里的大文件：按扩展名用 `.gitattributes` 管理；要用 LFS 必须在第一次提交二进制之前配置，否则要改写历史 | [git-lfs.com](https://git-lfs.com)、[GitLab LFS 文档](https://docs.gitlab.com/topics/git/lfs)、[Tower：LFS FAQ](https://www.git-tower.com/learn/git/faq/handling-large-files-with-lfs) |
| 5 | GitHub 免费账户 LFS 现为 10 GB 存储 + 10 GB/月流量（按量计费） | [GitHub Docs：LFS 计费](https://docs.github.com/articles/about-billing-for-git-large-file-storage)、[社区 FAQ](https://github.com/orgs/community/discussions/61362) |
| 6 | 多个项目共用一个库：想“项目里直接看得到、CI 不用额外配置”用 subtree；要严格锁版本、仓库很大用 submodule；只要一个目录用 sparse-checkout | [Opensource.com：submodule vs subtree](https://opensource.com/article/20/5/git-submodules-subtrees)、[mslinn：partial clone + sparse checkout](https://www.mslinn.com/git/600-partial-clone.html) |
| 7 | 清单要能被机器校验：JSON Schema + CI 自动检查 | [sourcemeta/jsonschema CLI](https://github.com/sourcemeta/jsonschema)、[GitHub Action：JSON Schema Validate](https://github.com/marketplace/actions/json-schema-validate) |

## 三、可以继续引入的方法和标准

| 参考 | 决策 | 用在哪 | 不采用 / 延后 |
|---|---|---|---|
| [W3C 设计令牌规范（2025.10 首个稳定版）](https://www.w3.org/community/design-tokens/2025/10/28/design-tokens-specification-reaches-first-stable-version) + [Style Dictionary](https://github.com/style-dictionary/style-dictionary) | **Adapt** | 把每种风格的颜色、字体、圆角、颗粒强度写成 DTCG 格式的 `tokens.json`，再用 Style Dictionary 一次导出 CSS 变量（独立站）、C#/JSON（游戏引擎）。`07-shades-of-off-white/palette.json` 是第一个可以改的 | 不为没有确定配色的风格硬写令牌 |
| [IPTC 数字来源类型](https://iptc.org/news/iptc-publishes-metadata-guidance-for-ai-generated-synthetic-media) | **Borrow** | 把 `ai_used: true/false` 细化成 IPTC 的受控词：`digitalCapture`（实拍）、`digitalCreation`（手工数字创作）、`trainedAlgorithmicMedia`（纯 AI 生成）、`compositeWithTrainedAlgorithmicMedia`（AI 参与合成）。Google、Midjourney、Shutterstock 都用这套词 | 不要求逐个文件写入 XMP |
| [C2PA 内容凭证](https://spec.c2pa.org/specifications/specifications/2.4/explainer/Explainer.html) | **Defer** | 独立站或视频要公开发 AI 生成内容时，保留生成工具写入的凭证、不要剥掉。注意：库里 12 个 SVG 图标已经内嵌了 C2PA 清单（每个约 8 KB），来源待核实，暂时原样保留 | 不自己签发凭证 |
| [REUSE 规范](https://reuse.software/spec-3.3) 的 `REUSE.toml` + `reuse lint` | **Defer** | 推到 GitHub 后，可以用一个 `REUSE.toml` 按目录声明许可证，跑 `reuse lint` 做第二道检查 | 现在 catalog.json 已覆盖同样信息，不重复维护 |
| GitHub Actions 自动校验 | **Borrow** | 推到 GitHub 后加一个工作流，每次提交跑 `check-catalog.py` | 推送前不需要 |
| 感知哈希去重（[pHash / dHash](https://benhoyt.com/writings/duplicate-image-detection)） | **Defer** | 图片超过 300 张时，加一个脚本找“看起来一样但文件不同”的重复图；Frontify 等 DAM 也是这么做的 | 现在 SHA-256 足够找完全重复 |
| 提示词版本管理（[LaunchDarkly](https://launchdarkly.com/blog/prompt-versioning-and-management)、[Braintrust](https://www.braintrust.dev/articles/what-is-prompt-versioning)） | **Adapt** | 每条提示词加 `id`、出处 URL、适用模型和版本、参数（如 `--sref` `--sw`）、收录日期、实测结果。模型一升级，旧提示词标“待复测”，而不是删掉 | 不上专门的提示词管理平台 |
| 视频模型官方提示词指南：[Runway Gen-4](https://help.runwayml.com/hc/en-us/articles/39789879462419-Gen-4-Video-Prompting-Guide)、[Google Veo](https://deepmind.google/models/veo/prompt-guide)、[Veo 3.1 官方博客](https://cloud.google.com/blog/products/ai-machine-learning/ultimate-prompting-guide-for-veo-3-1)、[Midjourney Style Reference](https://docs.midjourney.com/hc/en-us/articles/32180011136653-Style-Reference) | **Borrow** | 在 `07-video-kits` 加一页“官方提示词写法”，只收官方原文：Runway 的“主体动作 + 镜头运动 + 场景动作 + 风格”结构、用正面描述代替否定词（写 locked camera 而不是 no camera movement）；Veo 的“一镜一意”；Midjourney 的 `--sw` 0–1000、默认 100。Kling、海螺目前只找到第三方教程，先不收 | 不收没有出处的“万能提示词” |
| AI 视频“风格圣经”（[LongStories](https://longstories.ai/blog/style-consistency-ai-videos)、[Envato](https://elements.envato.com/learn/ai-video-consistent-character)） | **Build** | 每个视频项目开工前写一页：选定的 1 个风格（链到 `styles/`）、色板、光线、镜头焦段、材质、角色设定图、否定清单（直接引用不要做原则）。这是解决“风格不统一”最直接的办法 | 不做成通用模板库 |
| [Unreal 官方资产命名约定](https://dev.epicgames.com/documentation/unreal-engine/recommended-asset-naming-conventions-in-unreal-engine-projects?lang=en-US)、[Unity 风格指南](https://github.com/justinwasilenko/Unity-Style-Guide) | **Adapt** | 素材导入游戏工程时改成 `前缀_名称_变体`（如 `SK_Knight_A`、`T_Potion_D`）；素材库本身保持来源原名，方便回溯 | 不改素材库里的文件名 |
| [Lottie vs Rive](https://www.polarhedgehog.com/blog/rive-vs-interactive-lottie) | **Defer** | 网站或游戏需要可交互的矢量动画（按钮、角色表情）时，在 `library/` 加一类：纯播放用 Lottie，带状态机交互用 Rive | 现在没有需求 |
| [Eagle](https://en.eagle.cool) 本地参考图管理 | **Adapt（可选）** | 参考图越攒越多时，用 Eagle 管理 `refs/` 并按本库的 `domain/ object/ mood/ use/ tech/ theme/` 标签槽打标签 | 不把 Eagle 库当真源，真源仍是 catalog.json |
| 开源素材合集：[bradtraversy/design-resources-for-developers](https://github.com/bradtraversy/design-resources-for-developers)、[noobnooc/awesome-design-dev](https://github.com/noobnooc/awesome-design-dev) | **Borrow** | 作为找新素材的入口，候选先进 `00_收件箱` | 不整表搬进来 |
| [Atomic Design](https://atomicdesign.bradfrost.com/chapter-2) | **Reject** | — | 它是组件系统的方法，本库是风格和素材，不适用 |

## 四、建议的下一步（按收益排序）

1. **推到 GitHub 并加自动校验**：等设备会话能启动后提交、推送，再加一个跑 `check-catalog.py` 的工作流。
2. **`ai_used` 换成 IPTC 数字来源类型**：改动小，对独立站发 AI 内容和平台审核都有用。
3. **每种风格补 `tokens.json`**：先做米白层次和 Riso 两种，独立站可以直接用 CSS 变量。
4. **`07-video-kits` 加官方提示词写法页**，并给现有提示词补上模型版本和收录日期。
5. **第一个 AI 视频项目开工时写风格圣经**，验证这套库能不能真正让风格统一。
