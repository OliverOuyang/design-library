# 审美与设计积累库

这不是一个“好看链接”仓库，而是一套训练审美、设计感和产品感的长期系统。

这里会同时收录四类内容：

- **灵感源**：持续更新、值得反复浏览的网站、档案、出版物与社区。
- **个人卡片／积累**：你真正看过、拆过，并能说清为什么值得留下的案例卡片。
- **本地可预览素材**：已经核验来源与许可、可离线试听或观看的音效与 motion 样本。
- **问题与机会**：从产品、服务、文化与跨界参考中提出、验证和沉淀的设计机会假设；它不是事实或需求结论。

它也提供一条从积累走向生产的路径：当你拿到一个新的 App、网页、服务或数字产品设计任务时，可以直接使用 [`05_设计项目启动包`](05_设计项目启动包/README.md) 建立项目简报、关键流程、品味基线、界面系统、验证与交付门禁。积累库负责“见过什么、为什么好、可以提出什么假设”，项目启动包负责“这一次要解决什么、如何做对”。

## 从这里开始

### 我是来做产品、练审美或头脑风暴的

先打开 [`积累领域与检索地图.md`](04_规则与模板/积累领域与检索地图.md)，按你正在解决的任务而非素材格式选择入口：

- 做产品：从 UI／组件、交互／动效、产品／体验开始，把页面或流程拆成状态、行为、约束与可迁移规则。
- 练审美：从视觉／素材、文字／文学、声音／音效、艺术／跨界开始，记录构图、节奏、语言、感官或叙事的具体观察。
- 头脑风暴：从产品／体验、品牌／创意和艺术／跨界交叉取材，使用“机会假设”而非把灵感直接写成需求。
- 要复用本地文件：只在来源、许可、用途和完整性都可核验时进入 `素材资产`；UI 截图、流程录屏和网页参考默认是“参考／拆解”，不是可再分发的素材。

### 我要启动一个新的 App / Web 设计项目

1. 打开 [`05_设计项目启动包/README.md`](05_设计项目启动包/README.md)，先选择轻量、标准或上线级深度。
2. 复制 [`AI设计项目启动提示词.md`](05_设计项目启动包/AI设计项目启动提示词.md)，只补项目路径和已有信息，让 AI 完成盘点、选模板和首轮计划；未安装本库所引用 Skill 的 Agent 也可以直接执行提示词内的通用流程。
3. 先冻结问题、用户任务、关键流程和 Taste 基线，再进入高保真设计；不要用视觉精修掩盖产品定义缺口。
4. 在交付前完成状态、响应式、平台规范、可访问性与独立审核。

### 我要长期积累审美素材

第一次使用，按这个顺序：

1. 在 [`01_灵感索引`](01_灵感索引/) 里选一个方向，漫游 10～20 分钟。
2. 看到喜欢的内容，先丢进 [`00_收件箱`](00_收件箱/README.md)。
3. 如果两天后仍然觉得它好，把它整理成一张 [`03_个人卡片`](03_个人卡片/README.md)。
4. 当同一主题积累到 3 张以上，做成一个 [`02_主题合集`](02_主题合集/README.md)。

### 我要给游戏、独立站或 AI 视频定风格、找素材

打开 [`06_风格与素材库`](06_风格与素材库/README.md)。`styles/` 按视觉风格整理了 10 种风格的参考作品、公开提示词和“不要做”清单；`library/` 按类型整理了网页动效、图标、Emoji、游戏素材、字体和视频配方。每个文件的来源、作者、许可证和哈希都在 `catalog.json`，需要署名的见 `ATTRIBUTION.md`。动手前先读 [`不要做原则`](04_规则与模板/不要做原则.md)。

### 我要做 Oliver 自己的东西（网站、样品页、接单封面）

打开 [`07_Oliver风格包`](07_Oliver风格包/README.md)：“分析师批改过的报告”风格的颜色和字体变量、手绘批注 CSS、6 个手绘 SVG，以及 Fiverr / Upwork / 闲鱼封面和图集模板（网址传参，一条命令出图）。中文手写用平方江南体（只用于图片和视频，字体文件不在本库），网页上用马善政。

### 我要直接试听 / 观看经过筛选的素材

打开 [`素材资产/预览/素材库预览.html`](素材资产/预览/素材库预览.html)。首轮种子库含 6 个最小分类、每类 5 项：按压、悬停、切换音效，以及进入、加载、状态反馈动效。每项都可本地预览；来源、许可与采用边界见 [`素材资产/素材清单与许可.md`](素材资产/素材清单与许可.md)。

## 一个好条目应该留下什么

不要只写“好看”。至少回答三个问题：

- **观察**：具体是哪里好？比例、节奏、材质、声音、文案，还是反馈方式？
- **迁移**：它能被借到什么产品、页面或表达场景？
- **边界**：它为什么在这里成立？照搬时最容易学歪什么？

如果条目是组件、流程或创意方向，再补上“它服务什么任务／张力、在什么状态下成立、怎么用低成本试验验证”。参考、事实、假设和可执行资产不能互相冒充。

个人卡片按四档评级：

- `★☆☆☆ 存档`：有趣，但暂时没有明确用途。
- `★★☆☆ 启发`：至少有一个值得记住的点。
- `★★★☆ 可复用`：未来项目中很可能借鉴。
- `★★★★ 基准`：值得反复回看，是个人审美标尺。

## 维护节奏

每周留 30 分钟：

1. 清空或删减收件箱。
2. 精炼 3 张个人卡片。
3. 把至少 1 张卡片加入主题合集。
4. 升级 1 个基准案例，淘汰 1 个低价值条目。

详细规范见 [`04_规则与模板/收录规范.md`](04_规则与模板/收录规范.md)。

项目级规范、采用决策和跨 Session 接续记录见 [`项目治理`](项目治理/README.md)。根目录 README 是使用入口；治理目录只记录决策和证据，不重复维护使用说明。

## 使用与版权

索引中的“免费”通常指可以浏览或存在免费层，不等于素材可任意商用。下载、改编、嵌入或发布前，始终以原站最新许可证与条款为准。个人卡片尽量保留原始来源，不把他人的完整作品复制进本库。
