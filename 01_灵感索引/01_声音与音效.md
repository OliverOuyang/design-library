# 声音与音效

声音设计不是“给按钮加个响声”，而是用响度、音色、时长、节奏和沉默建立反馈层级。先研究声音如何对应动作，再考虑下载素材。

## 优先入口

| 站点 | 类型 | 为什么值得留 | 访问 / 许可 |
|---|---|---|---|
| [Cuelume](https://cuelume.dev/) | 可编程 UI 音效 | 14 种提示音用 Web Audio 实时合成，声音与 hover、press、release、toggle 等行为直接绑定 | MIT 开源 |
| [SND](https://snd.dev/) | UI 交互音效 | 专门面向 UX 的界面声音资产，适合比较不同控件的听觉触感 | 可浏览/使用；以站内 Terms 为准 |
| [plinq](https://plinq.dev/) | 程序化 UI 音效 | 极少依赖，把声音做成可参数化、可组件化能力 | MIT 开源 |
| [99Sounds](https://99sounds.org/) | 独立免费音效库 | 声音设计、环境采样和 Foley 素材质量稳定 | 免费 royalty-free；下载前复核单包说明 |
| [Freesound](https://freesound.org/) | 社区声音档案 | 体量大、标签与元数据丰富，适合精确找声源 | 每条许可不同，常见 CC0 / CC BY / CC BY-NC |

## 拆解 Cuelume 的观察框架

Cuelume 是本库的种子案例。打开后不要只试听，试着记录：

1. `press` 与 `release` 为什么要分成两个声音？
2. `success` 与 `error` 在音高走向、时长和材质上有什么区别？
3. 声音是否比视觉反馈更早、更晚，还是同步出现？
4. 连续触发会不会烦？静音后界面是否仍然成立？
5. 如果这是金融、儿童、医疗或创作工具，音色要如何变化？
